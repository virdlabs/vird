# Decisions

One line per design change after the v1.3 freeze: date, what, why. The design doc is not edited; this file wins where they differ.

- 2026-09-09 `assistant` calls the conversational model directly for critique and questions; `recognition` only identifies garments. Closes the missing model path in the system diagram. Style-profile notes are injected in the assistant's prompt, not recognition's.
- 2026-09-09 `SuggestedOutfit.garment_ids[]` replaced by a `suggested_outfit_items` table (suggested_outfit_id, garment_id, role, position). Deterministic swap needs per-role rows, and "suggested but rejected" becomes a join.
- 2026-09-09 `Outfit` gets `worn_at` and `logged_at` as timestamps; `logged_on` is a generated date from `worn_at` in the user's timezone. A date alone cannot order a wear against a same-day `WashEvent`, and it allows backdated logging.
- 2026-09-09 `RecognitionCandidate.recognizer_version` (string) added, mapping to a config record in code: detector, embedding model, score formula, threshold set. Makes silent-match debugging and benchmark results reproducible.
- 2026-09-09 `User.apple_sub` is nullable with a partial unique index. The fixed dev account exists before Sign in with Apple.
- 2026-09-09 `created_at` on every table, no exceptions.
- 2026-09-09 `RecognitionCandidate.resolution` gains `pending` (asked, not yet answered) plus `resolved_garment_id` and `resolved_at`; `Correction.prior_resolution` keeps what the candidate was before the override, so a false silent match (prior `auto`) stays countable after it is fixed.
- 2026-09-09 `RecognitionCandidate.alternatives[]` and `StyleProfile.excluded_garment_ids[]` replaced by `recognition_alternatives` (candidate_id, garment_id, rank, similarity) and `style_profile_excluded_garments` tables. Keeps per-alternative similarity for the benchmark, and a deleted garment cascades out instead of dangling in an array.
- 2026-09-09 `Garment.archived` is `archived_at`; `Garment` gains `deleted_at`, `role` (generated from category), `brand`, `wash_after_wears`; `pattern` and `material` are enums. Every attribute suggest reads is a typed column. A garment that was worn or suggested is soft-deleted, never hard-deleted, so history keeps its items.
- 2026-09-09 `OutfitItem.garment_id` and `SuggestedOutfitItem.garment_id` are `NO ACTION DEFERRABLE INITIALLY DEFERRED`. An immediate check breaks account deletion: the users cascade reaches garments before outfits and fails while outfit_items still exist (verified on Postgres 16).
- 2026-09-09 `Outfit` gains `timezone`, a copy of `users.timezone` at log time, so `logged_on` can be a stored generated column and the day stays fixed if the user later changes zone; and `from_suggested_outfit_id`, so "logged from a suggestion" is a key rather than jsonb detail.
- 2026-09-09 `embedding_models` registry (name, dims); `ExemplarEmbedding.vector` is an untyped `vector` column checked against the model's dims by trigger, so one table serves every model and a backfill is an insert.
- 2026-09-09 New `image_audit_log` table backs the privacy page's "every image sent" log. `Suggestion` gains `suggest_version` (the deterministic half, like `recognizer_version`); `Suggestion` and `RecognitionCandidate` carry `trace_id`.
- 2026-09-09 Foreign-key checks bypass RLS, so every policy's WITH CHECK also proves cross-tree references (garment, device, fit, suggestion) belong to the current user. Roles `vird_app` (no BYPASSRLS) and `vird_system` (BYPASSRLS) are created outside migrations; `CREATE EXTENSION vector` needs a superuser and happens before the first migration.
- 2026-09-09 Device pairing state (pending device, six-digit code) is not in the schema until the device phase; `devices` holds only paired mirrors.
- 2026-09-15 Every key from history to garments (outfit_items, suggested_outfit_items, recognition_candidates, corrections, recommendation_events) is `NO ACTION DEFERRABLE INITIALLY DEFERRED`, never `SET NULL`. A user deletes a garment softly (`deleted_at`); hard deletes happen only through the account-deletion cascade. This lets the candidate state CHECKs be strict (auto/confirmed resolve to best_match, corrected/new to a different garment, pending/unknown to none) instead of tolerating NULLs left by SET NULL.
- 2026-09-15 `recommendation_events` is append-only under RLS (select and insert only) and records a swap in key columns `role`, `from_garment_id`, `to_garment_id`; `detail` never holds an id. The outfit logged from a card is `outfits.from_suggested_outfit_id`, not an event field.
- 2026-09-15 `AnalysisAsset.expires_at` dropped. An asset's own 30-minute clock could never run out before its fit's, so the fit's `expires_at` and `closed_at` are the only TTL; the bucket lifecycle rule is the backstop.
- 2026-09-15 Nonempty CHECKs on every text column, keys included; `style_profiles.notes` rejects empty or NULL elements. `RecognitionCandidate.best_match_garment_id` is documented as never rewritten, so a declined proposal stays measurable.
- 2026-09-15 The garments RLS policy grants no DELETE (select, insert, update only), so the soft-delete rule is enforced rather than stated; a user session's hard delete affects zero rows and the store layer treats that as a bug. Devices keep FOR ALL for now.
- 2026-09-15 Enum arrays (`season_tags`, `excluded_categories`, `excluded_color_families`) reject NULL elements. A NULL inside an exclusion list would make suggest's `NOT (x = ANY(list))` NULL and filter out the whole closet.
